# CUDA 中英术语表与源码阅读约定

[中文首页](../../README.md) · [入门教程](./入门教程.md)

英文标识符是连接源码、编译器报错和官方资料的桥梁，因此保留函数、宏、类型、路径与 API 的原名；首次解释时同时给出中文。不要把 `threadIdx.x` 改成中文变量，也不要改 Python 绑定名称来实现“汉化”。

| 英文 | 中文 | 在本仓库中怎样理解 |
| --- | --- | --- |
| Kernel | 核函数 | GPU 上执行的并行函数；常以 `__global__` 标记 |
| Host / Device | 主机 / 设备 | 通常分别指 CPU 与 GPU 侧 |
| Thread | 线程 | 最简单版本中，一个逻辑执行者处理一个元素 |
| Block | 线程块 | 能通过块内共享内存与屏障协作的一组线程 |
| Grid | 网格 | 一次核函数启动的全部线程块 |
| Warp | 线程束 | NVIDIA CUDA 中通常为 32 个线程的执行分组 |
| SM | 流式多处理器 | 执行与调度线程块的重要 GPU 硬件单元 |
| Compute Capability | 计算能力 | GPU 架构能力的版本标识，不是显存容量 |
| CUDA Stream | CUDA 流 | 同一流中提交的操作遵循流内顺序，跨流另需考虑依赖 |
| Register | 寄存器 | 线程常用的片上存储资源 |
| Shared Memory / SMEM | 共享内存 | 本项目常用作块内协作的数据缓冲 |
| Global Memory / GMEM | 全局内存 / 显存 | 存储输入输出等设备数据 |
| Local Memory | 本地内存 | 线程私有的地址空间，名称不保证物理片上存储 |
| Coalesced Access | 合并访存 | 多线程访问模式便于合并为较高效的内存事务 |
| Alignment | 对齐 | 地址满足某个字节边界，如 `float4` 的 16 字节对齐 |
| Bank Conflict | 共享内存 Bank 冲突 | 访问竞争 bank 资源而可能产生额外处理轮次；需考虑广播等特例 |
| Reduction | 规约 | 将一组数据合并为更少结果，例如求和或最大值 |
| Scan / Prefix Sum | 扫描 / 前缀和 | 每个位置保存之前一段数据的累计结果 |
| Tiling | 分块 | 将大问题拆成便于映射线程和复用数据的小块 |
| Swizzle | 重排 / 交错映射 | 调整地址或任务映射以改善特定访问行为 |
| Warp Shuffle | 线程束数据交换 | Warp 内线程交换寄存器中的值 |
| Vectorization | 向量化 | 一个线程或一次操作处理多个数据元素 |
| Packed Read/Write | 打包读写 | 将多个元素的位模式合成更宽的内存访问 |
| Double Buffer | 双缓冲 | 用两组缓冲配合数据准备与计算 |
| Pipeline / Stage | 流水线 / 阶段 | 将工作分阶段调度并尝试重叠执行 |
| Occupancy | 占用率 | 活跃 Warp 数与硬件支持最大值的比率，不是速度唯一决定因素 |
| Tensor Core | 张量核心 | 执行支持格式的矩阵运算的专用硬件 |
| GEMM / GEMV | 矩阵乘法 / 矩阵—向量乘法 | 具体形状、布局及系数约定仍以接口为准 |
| SGEMM / HGEMM | 单精度 / 半精度矩阵乘法 | HGEMM 目录还包含 BF16，不能只由名称推断 dtype |
| FP32 / FP16 | 单精度 / 半精度浮点 | 不同位宽与数值表示能力 |
| BF16 | bfloat16 | 与 FP16 同为 16 位，但数值编码不同 |
| TF32 | TensorFloat-32 | Tensor Core 相关计算格式；不是通用 `float` 的同义词 |
| TMA | 张量内存加速器 | 支持的 GPU 架构上用于数据移动的硬件机制 |
| `cp.async` | 异步拷贝指令 | 名称下有不同变体，具体语义与支持情况看指令和架构 |
| `ldmatrix` | 矩阵片段加载指令 | 为特定矩阵计算准备数据布局 |
| `mma` | 矩阵乘加 | Matrix Multiply-Accumulate |
| JIT Compilation | 即时编译 | 运行时把 C++/CUDA 源码编译为可加载扩展 |
| Baseline | 基准实现 | 用于对照正确性或性能的参考实现 |
| Benchmark | 基准测试 | 在明确环境、数据和计时条件下测量性能 |
| Warmup | 预热 | 正式统计前先执行，减少首次运行因素 |
| Median / Mean | 中位数 / 算术平均数 | 不是同一种统计量，阅读本项目输出时尤其注意 |
| Speedup | 加速比 | 本项目使用参考耗时除以当前耗时 |
| Smoke Test | 冒烟测试 | 以小规模输入检查基本流程，不等于全面验证 |
| CTA / Cooperative Thread Array | 协作线程数组 | PTX 中对应 CUDA 线程块；不要与算法上的输入分块混淆 |
| Tile / Fragment | 数据块 / 矩阵片段 | 前者是算法划分的数据区域；后者常表示分布在线程寄存器中的计算片段 |
| Leading Dimension | 主维度步长 | 相邻存储列或行的起点间距；cuBLAS 的列主序参数需结合包装转换理解 |
| Inclusive Scan | 包含当前元素的前缀和 | 输出第 i 项包含输入第 i 项，区别于不包含当前项的 exclusive scan |
| Split-K | 沿规约维切分 | 将一段规约工作拆成多个分片，再合并；本仓库也把该思路用于 Softmax、采样等 |
| Online Softmax | 在线 Softmax | 分段维护最大值和指数和，合并时重缩放；不等于可以省略最终归一化 |
| LSE / LogSumExp | 指数和的对数 | Attention 分片合并时用于将各分片结果换到统一归一化尺度 |
| Logit | 未归一化分数 | 采样前的模型输出分数；与概率、概率的对数要区分 |
| Top-K / Top-P | 前 K 候选 / 累计概率截断 | 本采样实现先取 Top-K，再在候选内按 Top-P 截断 |
| CDF | 累积分布函数 | 将随机数落到累计概率区间，从候选中选择一个结果 |
| DP / TP / PP | 数据 / 张量 / 流水线并行 | 分别侧重切分输入数据、单层参数和模型层；本例固定单机两卡 |
| Micro-batch / Pipeline Bubble | 微批次 / 流水线气泡 | 用更小批次协调各阶段工作；气泡指阶段没有任务可做的空闲区间 |
| Pinned Memory | 页锁定主机内存 | 双流权重搬运示例使用的 CPU 内存；实际重叠仍依赖流和事件关系 |
| `mbarrier` / Phase Parity | 内存屏障对象 / 阶段奇偶位 | 本仓库用于 TMA 完成协调；阶段切换、到达计数和字节事务计数不能混为一谈 |

新增术语对应的具体用法见[模块完成表](./翻译进度.md)中的源码；PTX 指令和数据格式细节以 [NVIDIA PTX ISA](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html) 为准。

## 看到 C++ 语法时不要慌

`const T*` 限制通过该指针修改数据，但不自动验证地址有效；`reinterpret_cast` 改变类型视图，不转换数值；`#name` 将宏参数转成字符串；`name##_kernel` 拼接标识符；`if constexpr` 在编译期选择分支；`#pragma unroll` 是循环展开提示。它们与 CUDA 线程模型是不同层面的概念。

注释应解释“这一步为何必要”，尤其是线程映射、字节布局、尾部元素和同步关系。发现原实现限制时说明限制，不偷偷改变逻辑；确需修复时另做算法提交，便于审核。
